# UBSI API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a private, unofficial REST API aggregating UBSI web services (studentv2, elearning, elibrary, ejournal, repository, news) with Redis caching, running on 127.0.0.1:8300.

**Architecture:** A lightweight FastAPI server with modular scrapers powered by Scrapling (impersonate="chrome"). Redis provides a two-tier caching strategy (fresh with 60s TTL, last-known-good with no TTL) for resilient upstream downtime tolerance. All endpoints return a standardized JSON envelope.

**Tech Stack:** Python 3.12+, FastAPI, Uvicorn, Scrapling, redis-py, pytest.

**Spec:** `docs/superpowers/specs/2026-09-25-ubsi-api-design.md`

## Global Constraints

- Binding: 127.0.0.1:8300 only — never 0.0.0.0.
- No API authentication headers required internally (localhost security boundary).
- Secrets: read from `.env` only (never logged, never committed, never returned in responses).
- Parser isolation: pure parsing functions `parse_*(html) -> dict` tested against snapshot fixtures without live network calls.
- Upstream stability: exponential backoff retries with reasonable sleep intervals between requests.

## Review Focus

1. Upstream down / HTML changed: API must return last-known-good data with `stale_since` timestamp rather than crashing with 500.
2. Login session expiry: auto re-login on redirect to `/login` without requiring client retry.
3. Elibrary extreme latency: 60s timeout with 3x retry before returning 502 or cached data.
4. Math captcha variations: regex for arithmetic questions must handle spacing and unexpected token ordering.
5. Incomplete upstream tables: absent table rows or columns must return empty lists or nulls, never indexing errors.
